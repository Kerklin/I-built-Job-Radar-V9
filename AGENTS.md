## 2. Rules
1. Never invent qualifications, dates, employers or numbers about Damir. Not documented → `[UNVERIFIED]`.
2. Less is more: max 7 tracked files plus generated ones. No packages, no paid services, no AI in the scheduled run.
3. Never add a `uses:` action to radar.yml. Plain git + python3 is the Node.js fix.
4. Respect robots.txt and access blocks. Never bypass them; keep a manual link instead.
5. Scoring change → config.json first → `--test` 100 % → commit. Wrong result → add it to benchmark.json (ask first), then fix.
6. A FAIL source is a source problem, not a scoring problem. Fix its URL or set `"off": true`.
7. Never read, print or commit .env, keys or secrets.
8. End of session: update HANDOFF; add a LESSONS line if something went wrong.

## 3. Skills
**vacancy-screen**: eligibility per hard requirement PASS/FAIL/UNCLEAR → fit /100 (technical 35, sector 20, UN/donor 15, level 15, location 10, language 5) → gaps ✅/⚠️/❌ → APPLY ≥70 · CAUTION 55–69 · NO <55 → top 3 HR risks. One screen.
**cv-tailor**: map every vacancy keyword to documented evidence; ATS headings, one column, "Month Year"; real titles; "Bosnian/Croatian/Serbian: Native"; CV + keyword report + match → REVIEW.
**cover-letter**: one page or the character limit; 2–3 evidence examples with numbers (17 preschools, 7 CSWs, EU IPA 2020); address the main risk in one sentence; never the "Bangui team" sentence → REVIEW.
**add-source**: Oracle Recruiting Cloud career site → `"type":"oracle"` + host + site (CX_…). RSS → `"rss"`. Any page with job links → `"auto"` + `link_has`. Give several `urls` as fallbacks. Test with `python radar.py --source NAME`; items must be > 0.
**REVIEW**: every claim ✅/⚠️/❌; mandatory requirements met/gap; ATS; character limits; for scoring changes, likely new false positives or misses → **PASS** or **FIX FIRST**.
